# Code of Conduct

## The short version

Be decent. Assume the other person is acting in good faith. Argue about the
code, never about the person writing it.

## What is expected

- **Take the technical disagreement seriously and the ego lightly.** Being
  wrong about a design decision costs nothing; defending it past the evidence
  costs everyone time.
- **Say what you mean.** Vague criticism is harder to act on than blunt
  criticism.
- **Assume the report is real.** A bug report that seems impossible is usually
  a bug you have not understood yet.
- **English is the working language**, but nobody is judged on their command of
  it. If a report is clear enough to act on, it is clear enough.

## What is not

Personal attacks, harassment, discriminatory language, or sustained disruption.
Publishing someone's private information. Sexualised language or imagery.

None of these become acceptable because the technical point underneath them was
correct.

## Reporting

Open a private security advisory or contact the maintainer directly. Reports are
handled privately, and the reporter is never named to the person reported
without asking first.

The maintainer may edit, remove, or reject any contribution, and may block
accounts, for behaviour that violates this document.

## Scope

Issues, pull requests, discussions, and anywhere someone represents this
project.
